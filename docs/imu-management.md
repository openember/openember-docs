---
title: IMU 采集与设备管理
---

OpenEmber 的 IMU 接口将采集、配置、校准分开：`IImu` 提供样本和生命周期，`IImuConfiguration` 声明支持的参数及 RAM / Flash 能力，`IImuCalibration` 提供具体校准操作。产品通过标准 Hardware Interface IMU endpoint 装配驱动，不需要为每种型号重建消息层。

## 唯一设备 owner

启用 `OPENEMBER_COMPONENT_IMU_LINK` 后，`openember::imu_link` 的 `ManagedImu` 包装唯一驱动实例，交给现有 `MakeImuEndpoint` 使用。采集、参数查询、写入、重连和波特率探测均在同一 acquisition 线程执行；Web 或其他客户端通过消息提交，不直接打开串口。HI 仍负责生命周期和样本发布。协议由 `openember-msgs` 的 `sensor/v1/imu.proto` 定义，服务端点为 `/sensors/imu/<sensor_id>/rpc`，位于对应机器人的 Link 命名空间。

配置是可选能力。频率、波特率、输出字段、校准和持久化选项均以 capability 为准；未声明支持的操作必须拒绝。产品的设备连接与安装参数仍由 YAML 管理，修改设备运行参数不会自动修改部署文件。

## 使用和维护互斥

认证身份分 `observe`、`use`、`maintenance`，各身份使用独立密钥。使用租约供运控等消费者保留 IMU：持有期间不能配置或重新连接设备。维护租约反过来阻止新消费者取得使用权。产品通过有界的 `maintenance_check` 回调提供维护前提，例如持续新鲜的电机物理失能确认；缺失或失效时返回拒绝原因。产品必须确保所有动作 owner 在请求电机许可前取得 IMU 使用租约。

使用租约为 2 秒，需要消费者续租；维护租约为 30 秒，正在执行的命令结束前不释放设备独占。网络请求带服务会话、唯一请求 ID 和不超过 3 秒的服务端单调时钟期限。服务缓存最近结果，重复 ID 及相同请求返回原结果，内容冲突则拒绝。丢失响应时查询原请求结果，不自动重发设备命令。

当前传输仅接受本机回环 Link locator。请求与响应通过 AES-256-GCM 绑定机器人、端点、方向和来源身份；凭据文件要求当前用户所有且无组/其他用户权限，建议 0600，创建不覆盖已有文件。日志只记录来源、操作、请求 ID 和结果，不记录密钥。

## 观测时间和坐标系

管理状态同时提供原始样本、安装转换后的样本、owner 会话及主机时钟身份。运控消费者可以从认证快照建立绑定，但必须保留原始接收时间、序号和采集时钟域，检查样本新鲜度与主机时钟一致性。公共遥测 topic 的到达时间不能证明观测采集时间，也不能单凭收到 topic 为实机控制签发许可。

设备读取失败时 owner 保留管理入口供显式重新连接；它不重放旧样本，也不把旧样本重新标成新鲜。设备维护期间观测不作为可用控制输入。产品策略可以选择记录事件或停止，但不能通过修改时间戳掩盖过期数据。

## RAM、Flash 与结果

每次写入明确指定 RAM 或 Flash。RAM 只临时应用；Flash 请求保存到设备。逐字段结果包含 `applied`、`rejected`、`unconfirmed` 和设备说明。ACK 或当前值读回只证明设备接受 / 当前运行值符合预期，不能证明断电持久化。界面应分别展示应用结果与持久化证据，不能将 `unconfirmed` 或仅收到 ACK 的校准显示为完成。

波特率探测只切换主机连接参数并查询，结束后恢复部署波特率；重新连接也使用部署参数。波特率写入的换速、查询和失败确认由具体驱动在独占连接上完成。通用层不猜测协议、不自动更新 YAML，也不以重试覆盖未知执行结果。

静态标零、磁校准等操作各自声明能力与条件；不同设备的校准行为不能用一个“通用成功”掩盖。原生设备只报告已接受时，应保留该状态，完成判断需要协议定义的证据。
